# План: бот для оцифровки конспектов

## 1. Выбранная архитектура (коротко)

```
Телефон (Telegram)                     Сервер                                   GitHub                 Ноутбук
┌────────────────────┐   фото    ┌──────────────────────────────┐  git push  ┌──────────────┐ git pull ┌─────────────┐
│ Бот + Mini App     │ ────────► │ Бот + веб-сервер (Python)    │ ─────────► │ приватный    │ ───────► │ Claude Code │
│ загрузка, правка,  │ ◄──────── │ распознавание: Claude Code   │            │ репозиторий  │          │ (учебный    │
│ сохранение         │   текст   │ в фоновом режиме (claude -p) │            │ «Учёба»      │          │  проект)    │
└────────────────────┘           └──────────────────────────────┘            └──────────────┘          └─────────────┘
```

Принятые решения и причины:

| Вопрос             | Решение                                                             | Почему именно так                                                                                                                                                                       |
|--------------------|---------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Где хранить записи | **GitHub** (ваш вариант 2.2)                                        | Это реализуемо и проще всего. Ноутбук может быть выключен — записи просто ждут в репозитории. Claude Code уже умеет работать с git. Бонусом получаете историю правок и резервную копию. |
| Чем распознавать   | **Claude Code на сервере по вашей подписке**                        | Новых трат нет. Claude хорошо читает рукописный текст и формулы. Подробности и риски — в разделе 3.                                                                                     |
| Интерфейс          | **Telegram Mini App** (веб-страница, открывающаяся внутри Telegram) | Это единственный удобный способ дать редактор текста и выбор папки прямо в телефоне.                                                                                                    |
| Доступ             | Проверка вашего Telegram ID из файла настроек                       | Посторонний человек, нашедший бота, получит отказ.                                                                                                                                      |

Варианты 2.1 (прямое подключение к ноутбуку), 2.3 (облако) и 2.4 (хранение только на сервере) отброшены: первый ломается, когда ноутбук выключен, а второй и третий требуют дополнительных подключений для Claude, тогда как git он умеет «из коробки».

## 2. Как это будет работать для вас

1. Вы открываете бота в Telegram и нажимаете кнопку «Оцифровать».
2. Открывается Mini App. Вы выбираете семестр и предмет. Список берётся из папок вашего репозитория, поэтому вводить вручную ничего не нужно. Затем пишете тему (необязательно) и загружаете несколько фото.
3. Сервер распознаёт текст. Обычно на это уходит от нескольких секунд до минуты, но точное время нужно проверить на реальных фото.
4. Вы видите текст в редакторе. Можно переключиться в режим просмотра, где формулы и списки отображаются красиво. Исправляете ошибки.
5. Нажимаете «Сохранить». Файл появляется в репозитории по пути
   `<N> семестр/<Предмет>/Записи/2026-11-07_<тема>.md`
6. На ноутбуке, когда вы запускаете Claude Code в учебном проекте, он сам выполняет `git pull` (скачивает свежие изменения с GitHub) и уже видит новую запись.

**Формат файла.** Предлагаю `.md` (Markdown — обычный текст с простой разметкой) вместо `.txt`. Это тот же текстовый файл, но в нём можно выделять заголовки и записывать формулы в формате LaTeX, например `$x^2$`. Claude читает такой текст лучше. Если хотите строго `.txt`, это меняется одной настройкой.

В начале каждого файла будет короткая шапка с датой, предметом и темой, чтобы Claude сразу понимал контекст.

## 3. Распознавание: почему Claude Code на сервере

На сервер устанавливается та же программа Claude Code, что у вас на ноутбуке. Вы один раз создаёте на ноутбуке долгоживущий токен (ключ входа) командой `claude setup-token` и кладёте его в настройки сервера. После этого бот вызывает Claude в фоновом режиме командой `claude -p "<инструкция>"` и передаёт ему пути к фото. Claude возвращает распознанный текст.

**Плюсы:** не нужен платный API (программный доступ к модели с оплатой за каждый запрос), качество распознавания высокое.

**Честные минусы и риски:**
- Распознавание расходует лимиты вашей подписки, общие с вашей обычной работой в Claude Code. Для конспектов это немного, но если вы упрётесь в лимит, бот временно не сможет распознавать.
- Схема рассчитана только на личное использование. Давать бота другим людям под вашей подпиской нельзя.
- Работоспособность нужно проверить первым шагом (этап 1 ниже), пока это не проверено.

**Запасной вариант**, если Claude Code на сервере не заработает: Google Gemini API (программный доступ к модели Gemini от Google). У него есть бесплатный тариф, и рукописный текст он распознаёт хорошо. Минус: на бесплатном тарифе Google может использовать ваши данные для обучения моделей. Делать оба варианта сразу не будем: переходим на запасной только если основной не подойдёт.

Вариант 6 (просто складывать фото в репозиторий, а распознавать уже на ноутбуке) тоже рабочий и самый дешёвый, но он убирает возможность сразу проверить и поправить текст, поэтому он не выбран.

## 4. Технологии

Сначала сервер планировался на Python в Docker. При реализации его перевели на Node.js: ваш навык развёртывания `deploy` выкладывает на сервер только Node.js-приложения, и Claude Code тоже ставится как пакет Node.js.

- **Node.js 22** — язык и среда, на которых работает сервер.
- **grammY** — библиотека для Telegram-бота.
- **Express** — библиотека для веб-сервера, который отдаёт Mini App и принимает фото.
- **Claude Code** — ставится зависимостью проекта и запускается с отдельной папкой настроек, поэтому чужие настройки Claude на сервере ему не мешают.
- **Mini App** — одна HTML-страница на обычном JavaScript без сложной сборки, с официальным скриптом Telegram `telegram-web-app.js`. Фото ужимаются прямо в телефоне перед отправкой, поэтому загрузка идёт быстрее.
- **git** на сервере — локальная копия вашего учебного репозитория `mishgancheg/study`. Перед каждым сохранением выполняется `git pull --rebase` (подтянуть свежие изменения), затем `commit` (зафиксировать) и `push` (отправить на GitHub).
- **Навык `deploy`** — служба systemd (системный механизм Linux, который держит программу запущенной и перезапускает её после сбоя) за nginx (веб-сервер, который отдаёт сайт по защищённому соединению HTTPS). Раз в минуту навык сам подтягивает новый код с GitHub. Адрес: `https://textrec.bazilio.ru`.

Безопасность: каждый запрос из Mini App подписан Telegram (поле `initData`). Сервер проверяет эту подпись и сравнивает ваш ID со списком разрешённых в файле настроек. Доступ к GitHub даётся через deploy key — ключ, который открывает доступ только к одному репозиторию, а не ко всему вашему аккаунту.

Оригиналы фото хранятся на сервере 30 дней (на случай, если нужно перепроверить), в репозиторий не попадают, чтобы он не разрастался.

## 5. Этапы работы

1. **Проверка распознавания.** Сделано: на сервере Claude Code отвечает по токену подписки, а тестовая рукописная страница с формулами распознаётся примерно за 7 секунд на модели Opus. На ваших настоящих фото ещё не проверено.
2. **Бот и Mini App.** Сделано и проверено локально: загрузка фото, распознавание, редактор, просмотр с формулами, сохранение в репозиторий. Этап «бот без Mini App» пропущен, потому что Mini App сделан сразу.
3. **Размещение на сервере.** Ждёт DNS-записи `textrec.bazilio.ru` и связи с сервером.
4. **Настройка ноутбука.** Автоматический `git pull` при старте Claude Code (инструкция ниже).

## 6. Что нужно сделать вам

### 6.1. Telegram
1. Напишите [@BotFather](https://t.me/BotFather), отправьте команду `/newbot` и придумайте имя. В ответ придёт токен бота — длинная строка вида `123456:ABC...`. Это пароль бота, никому его не показывайте.
2. Узнайте свой Telegram ID: напишите боту [@userinfobot](https://t.me/userinfobot), он ответит числом. Это число попадёт в настройки как единственный разрешённый пользователь.

### 6.2. GitHub
1. Создайте **приватный** репозиторий, например `study`, и перенесите туда свою учебную папку. Если git на ноутбуке ещё не настроен, это сделаем вместе.
2. Ключ для сервера (deploy key) я сгенерирую сам при настройке сервера. Вам нужно будет только вставить его в репозитории: **Settings → Deploy keys → Add deploy key** и поставить галочку **Allow write access** (разрешить запись).

### 6.3. Claude Code
На ноутбуке выполните в терминале `claude setup-token`. Команда откроет браузер для входа и выдаст токен. Его нужно будет передать мне при настройке сервера (так же, как токен бота).

### 6.4. Сервер
Нужны адрес сервера, логин и пароль или SSH-ключ (ключ для входа на сервер без пароля), а также домен. Если домена нет, бесплатный поддомен заведём на DuckDNS.

### 6.5. Автоматический `git pull` в учебном проекте
В корне учебного проекта создайте файл `.claude/settings.json` с таким содержимым:

```json
{
  "hooks": {
    "SessionStart": [
      {
        "hooks": [
          { "type": "command", "command": "git pull --ff-only" }
        ]
      }
    ]
  }
}
```

Это хук (hook) — команда, которую Claude Code сам выполняет в определённый момент. Здесь момент `SessionStart`, то есть начало каждой сессии. Команда `git pull --ff-only` скачивает новые записи с GitHub и ничего не делает, если у вас есть свои несохранённые конфликтующие изменения. Это надёжнее, чем просто написать «делай git pull» в инструкциях, потому что хук срабатывает всегда, а инструкцию модель может пропустить.

Дополнительно в `CLAUDE.md` учебного проекта стоит добавить строку:
> Записи с пар лежат в папках `<N> семестр/<Предмет>/Записи/`. При создании учебных материалов опирайся в первую очередь на них.

### 6.6. Что прислать мне для старта
- токен бота;
- ваш Telegram ID;
- адрес репозитория на GitHub;
- данные сервера и домен (или согласие завести поддомен на DuckDNS);
- 2–3 фото конспектов для проверки распознавания (этап 1).
